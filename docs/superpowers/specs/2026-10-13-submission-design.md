# Shared submission workspace
Approved in conversation: broker and underwriting portals share a submission record. Three primary screens: broker intake, assistant evidence review, broker correction workspace. Email is a simulated notification linking to portal; issue details remain in the portal.

Frontend-only clickable prototype using fictional data. No actual document extraction, authentication, email, or binding. Broker can update application or submit sample replacement documents, or ask for help. Assistant verifies possible discrepancies, approves requests, and checks returned evidence. Updated files reopen relevant checks. Final completion requires checklist and discrepancy verification; completion is not authorization to bind.

Use an accessible responsive white/cool-gray interface, violet accent, left navigation, restrained typography, source document facsimiles with highlights and labels. Persist demo progress locally. Provide reset and scenario shortcuts for reviewers.

## Revision from user feedback
Role and screen are separate. Broker navigation: Submission, Requested changes. Assistant navigation: Submission, Evidence review. Only the top prototype role control changes identity. Submit/return keep the broker; publish/verify keep the assistant. Initial discrepancies appear during broker draft only; confirmed requests appear in broker correction comparison after assistant publication. Under-review submission fields are read-only without intake discrepancy styling. Status is prominent below functional task titles. Removed explanatory sidecard, human review sidecard and shared activity navigation.
